## Reproduction and Change

The user supplied an affected Tencent Cloud task. A read-only query confirmed `history_mode=legacy`, the requested name in `threads.name`, and the old visible name in `threads.title`. The old mutation chose whichever name column existed, and NexusHub also preferred that column. Official Codex uses legacy `title` and paginated `name`, explaining the disagreement after rename. The installed cloud CLI is 0.153.4.

Rename now calls only `initialize`, `initialized`, `thread/name/set` and `thread/read` through a bounded local CLI process. Success requires the same task ID and requested native name on readback. Timeouts and mismatched readback fail visibly; there is no SQL fallback. The native operation maintains the name index and handles each history format. NexusHub's read model uses the corresponding native column. CLI discovery and bounded protocol framing reuse the existing internal client; Goal recovery and notification algorithms are unchanged. Linux retains auth, CSRF and audit; Tauri awaits the native operation without blocking its command dispatcher. No RPC/invoke DTO, configuration, database schema or public allowlist changes.

Official source at `openai/codex` commit `3d2ee51ca2d5db578f328aa75e20aa22c0197c9a` confirms history-format persistence and same-process notification broadcasting. Two isolated native app-server processes read each other's persisted names but do not exchange name notifications. Persistent native correctness is verified separately from live Desktop cache refresh; no claim is made that a new stdio process can notify an existing unrelated Desktop connection.

The native rename handler excludes archived tasks. The archived menu now disables rename with the shared `取消归档后可改名` tooltip; the backend rejects it before starting a CLI or changing metadata. The existing explicit restore action enables rename again. NexusHub never temporarily unarchives a task as a hidden part of rename.

The Grok report concerns new messages appearing late. The previous detail interval was 15 seconds, list interval 30 seconds, manual refresh omitted the detail, and long histories did not follow the latest output. Details now poll at 1 second while running and 2 seconds otherwise; lists poll every 5 seconds. A hidden mobile detail does not poll. New messages follow the bottom, while scrolling back preserves the reading position. Manual refresh includes the visible detail.
