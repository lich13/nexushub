# v0.1.159 Acceptance Record

Status: published and deployed, but NOT ACCEPTED. Final inspection found 15px horizontal overflow at a 320px viewport with classic scrollbars. The old overflow assertion compared against `innerWidth`, which includes scrollbar width. Corrective release `v0.1.160` removes the body minimum width and validates against `documentElement.clientWidth` with real classic scrollbars enabled. The `v0.1.159` tag is unchanged; final corrective evidence and task cleanup are recorded in [v0.1.160 acceptance](./v0.1.160-acceptance.md).

## Scope and Baseline

The baseline is `main@1ad2756a3b0bf12e8514196968e521f56921980a`. Before this task, the installed macOS App, its helper and Tencent Cloud webd reported `0.1.158`; Tencent systemd and loopback healthz were healthy. macOS ARM64 Tauri, Linux x86_64 Tauri and Tencent headless webd remain supported. Codex, Grok Build, Probe and Settings remain available.

The official Codex repository and desktop product page are visual references, not a claim that NexusHub uses the Desktop UI source. No official Codex application, user history, credentials or database schema was changed.

## Delivered Behavior

- A single system-following theme defines root semantic tokens. The `--text`/`--chat-text` and border cycles, old compact override sheet and retired composer/inspector styles are removed. The old light login contrast failure was reproduced in a real browser at 1.06:1 before the change.
- Desktop navigation is 152px, collapsing into a 48px rail in normal layout. Lists are 276px and reading content is bounded to 780px. Mobile uses one 767px breakpoint and shared 54px/58px navigation dimensions. Menus support arrows, Escape and focus return, including WebKit's unfocused pointer-button behavior.
- Codex has an explicit archive view for restoration. Plan, question and answer history remain read-only; answer blocks are classified before question blocks so their content is visible. No retired action was restored.
- Hidden query sections stop polling. Started jobs remain observed until terminal state, then leave the mutation cache. Running operations block duplicate submissions; failures and job output remain visible. Log maintenance requires a successful dry-run followed by explicit confirmation.
- Bark and restricted Goal recovery use independent save flags. v0.1.159 corrected the outbound disable payload, but final corrective testing found that reloading a configured key could re-enable its displayed toggle, and a delayed save callback could replace a later edit. Both remaining cases and the duplicate-submit window are corrected and tested in v0.1.160.
- Five unused dependency declarations, the uncalled Sentinel shell, old desktop home/model/permission chain and retired action helpers are removed. The six frontend runtime dependencies and two independent Rust workspaces remain. Lockfiles contain no unrelated package upgrade.
- Tauri's hook owns the single frontend build. Frozen installs are reused by workflow packaging. Explicit skip mode validates existing relative assets and binds the actual packaged directory to that validation, including a custom `WEBUI_DIR`. Server assets are built separately with `/nexushub/` base.
- Linux AppImage smoke records both window pixels and the existing desktop boot probe: mounted shell, all four navigation entries, native runtime and no login/security gate. Boot diagnostics now use the platform's actual log directory.
