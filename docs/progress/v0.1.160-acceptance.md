# v0.1.160 Corrective Acceptance

Status: implementation in progress; not accepted.

## Why a Corrective Release

The complete v0.1.159 simplification is documented in [its implementation record](./v0.1.159-acceptance.md). Implementation `e5bd7f1417b2e56bf97ecd0ef2d41ec11318dcb2` passed CI `34117252357` and Release `34117847441`; all 15 assets, updater signatures, macOS/Tencent deployment and isolated official-helper replay passed. Final screenshot inspection then found horizontal scrolling at 320px with classic scrollbars: `innerWidth=320`, `clientWidth=305`, `scrollWidth=320`. The old headless browser configuration hid scrollbars and compared overflow to `innerWidth`, so it missed the defect. v0.1.159 is not accepted and its tag is not rewritten.

v0.1.160 removes the body minimum width. Chromium now retains classic scrollbars, the fixture waits for the settings form and asserts a real scrollbar gutter, and overflow uses `documentElement.clientWidth`. The original 320px light case failed before this CSS change; both 320px themes passed after it. The fresh browser gate also reproduced a late successful Probe save overwriting the next edit before its pending state rendered. Save completion now normalizes only the submitted draft; subsequent edits remain intact. The regression checks both the failed request payload and the retained input. No runtime API, notification/recovery algorithm, data format, dependency version or supported platform changes.

CI rendering also now installs CJK fonts, and an independent exact-tag AppImage workflow verifies a downloaded release with its checksum and a nonblank native four-workspace shell. The initial validation environment omitted Gdk introspection; that environment dependency is fixed in `23c726e0f8c23bd47eed7054b139995fb4976bf9`, whose four CI jobs passed in `34119754143`. Exact-tag v0.1.159 AppImage smoke then passed in `34119776523`. These validation changes do not rewrite any released binary.

Probe save buttons share an immediate in-flight guard, closing the duplicate-click window before React Query renders pending state. The guard holds through settlement, so the saved draft cannot be confused with another request. A delayed-response browser regression dispatches two same-turn save events and verifies one request and disabled inputs. Reloading a disabled Bark configuration now respects `enabled=false` even when a device key is configured. The browser fixture mirrors the server's nested save input and flattened notifications response, and verifies the visible saved toggle as well as the submitted flags.
