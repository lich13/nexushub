# NexusHub 当前状态（维护者）

## 当前版本

当前维护版本为 1.3.0。正式发布状态、中文说明与八项资产以 [GitHub Release](https://github.com/lich13/nexushub/releases) 为准，对应提交的完整回归结果见 [CI](https://github.com/lich13/nexushub/actions/workflows/ci.yml)。历史改动与测量记录由 Git 和 Release 保留。

## 当前改动

- 本机 Codex 主线程通过已核验 owner 的原生桌面执行新建、续聊、补充、停止和默认/Plan 模式；短生命周期 helper 只读目录和创建空线程。
- NexusHub 自有加密待发送队列替代不安全的原生整表写入。认领先落盘，结果不明不重发；重启和断线后保留暂停项，失败补充不能变成新回合。
- 文件选择与原生技能、应用、插件目录授予不透明引用，绑定机器修订和线程；发送前核对文件身份。审批绑定完整请求和文件 diff，问答保留原生身份与秘密输入。
- 协作区通过有界频道接收原生状态，切换失败也清空旧连接；隐藏、切换线程和迟到响应不恢复旧审批或队列状态。
- API 协议仍为 2，新增能力只属于 macOS Tauri；Linux、远程和子线程阅读、管理保护、Bark 和既有安全加固保持。

## 验证范围

核心阶段已执行受影响的协议、引用、队列、迁移、Tauri 授权、前端生命周期与请求渲染测试，以及两套 workspace 的 fmt/clippy、类型、构建、契约和隐私检查。完整回归和跨平台构建沿用对应提交的三项 CI，包括 Chromium/WebKit 与 macOS headed 性能门禁。命令见 [README 开发](../../README.md#开发)，不把既有测试或初次失败后的局部复验记成全套通过。

专用原生线程已核验空线程创建、发送、Plan 问答、补充和停止。应用目录实机请求曾超时，真实审批、引用操作和视觉体验未据此宣称通过；目录缓存整体过期/淘汰路径未单独覆盖。数据与身份负面测试均使用隔离 fixture。依赖审计结果以对应 CI artifact 为准，不等同于无风险承诺。

## 待用户验收

安装后分别选择本机与远程机器，检查三个 Provider 的列表、详情、历史分页、搜索、附件、Plan 和子智能体阅读；已有连接、通知配置和管理保护应保持。

本机 Codex 在原生桌面打开主线程后连接，检查发送、排队、补充与停止，模型/思考强度/Plan、文件/图片与原生引用，以及审批和问答。断线或重启后队列暂停，结果不明需先在 Codex 核对；远程、归档和子线程没有发送入口。详细步骤见 [README](../../README.md#本机-codex-协作) 和[部署手册验收](../cloud-deploy-runbook.md#升级验收)。真实功能、视觉及日常使用由用户确认，安装仅检查成功状态、版本和启动。

## 保留边界

API 协议保持 2，既有 RPC、DTO 与 tombstone 语义不变；新增七个桌面专属命令、可选能力和 NexusHub 自有加密发送记录。保留旧服务回退与有效迁移，移除条件见[兼容与自有数据迁移](../ARCHITECTURE.md#兼容与自有数据迁移)。不直接修改原生会话或队列，不回退到独立 CLI 执行；Keychain、常量时间认证比较、禁止重定向与 systemd 权限边界保持。

资产范围为 macOS ARM64 DMG/checksum、updater archive/signature、latest.json 和 Linux x86_64 API tarball/checksum/signature，共八项；updater 仅映射 darwin-aarch64。首次签名升级由可信客户端验签，先升级 API，再安装正式 App，只做必要部署成功、运行版本与启动检查。正式产物、会话、连接、凭据与共享缓存保留；只清理本轮明确归属的暂存。
