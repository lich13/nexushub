# NexusHub 当前状态（维护者）

## 版本与交付阶段

**1.2.10 收尾发布中。** 1.2.9 的阅读布局、子智能体和 Rust 测试修复已发布；正式 App 远程验收发现的钥匙串阻塞已完成源码修复，等待新补丁正式安装后验证。采用普通增量提交，不替换 1.2.9 标签或资产。

## 已完成实现

- 标题栏、正文与活动摘要收紧并对齐；移除重复 Provider 标签，复制按钮使用不占正文行高的侧边动作位。
- 创建调用和结果配对子智能体，支持精确任务路径、嵌套关系与自身回合状态；异常关联不猜测。
- 右侧详情独立分页和滚动，复用消息、工具、Plan、附件、路径、记忆过滤及 AGENTS.md 折叠；关闭后恢复父线程位置与焦点。
- 共享只读契约贯通 core、Linux API、Tauri 和 WebUI；子线程附件绑定原主线程并验证来源。
- Hook 测试只使用本次 Cargo 构建的二进制，保留真实 CLI、等待及去重断言。

远程现有会话没有原生子线程。使用正式服务二进制、独立配置和回环端口完成 63 项隔离夹具断言，覆盖父子/嵌套、505 条工具分页、附件、关系及路径保护、鉴权和原生文件不变；临时服务及数据已清理。此结果不代表真实远程子线程验收。

正式 App 已验证三个真实 Codex 子智能体的打开、关闭、历史分页、Escape、焦点返回和父线程可见位置保持；三个 Provider 的紧凑布局及复制反馈通过观察。真实嵌套子智能体没有可用样本，由夹具覆盖；复制反馈不替代剪贴板字节核验。关闭 App 后，正式 monitor 仍运行且没有 TCP/UDP 监听。

## 正式入口阻塞

App 切换腾讯云后，Codex 列表在空搜索和“全部”筛选下持续加载超过两分钟，没有线程行或明确错误；设置中的远程版本读取也未通过。同参数的已认证 HTTPS 请求正常返回，因此不能将 API 检查等同于 App 远程验收。

只读进程采样发现两个远程调用同时停在 `get_password`、`SecKeychainFindGenericPassword` 和 `ItemImpl::getData` 的互斥等待中，尚未进入 HTTP 请求；没有观察到系统认证对话框。阻塞的具体触发条件仍需在核心实现阶段验证，并处理凭据访问的并发、阻塞隔离和等待反馈。未修改钥匙串、凭据、已发布标签或资产。

App 已恢复本机 Codex 阅读页，列表正常，正式服务与 monitor 保留。发布页已知问题提示的写入返回 HTTP 400，回读确认尚未更新；未重复提交，原因待查。

核心修复已落地到源码：凭据读写共用串行后台通道，读取等待上限 15 秒；超时或调用方取消不会释放仍在执行的原生操作所持许可。保存和移除连接以完整事务执行，连接锁保持至提交或回滚结束；等待凭据和能力检查后重新核对连接身份，旧请求不继续发出业务调用。未新增凭据缓存、RPC 或配置字段。

受管 `rust-tests` 任务 `27f56e779e004d4584494ce9` 已通过，包含 9 项新增并发、超时和取消用例；`rust-clippy` 接续任务 `5bbb638126a54abeb2a3c7c3` 通过且源码快照一致。工作树及可达 Git 对象隐私扫描通过。修复提交 `317c0922bca251fc8e12c363f6256e68e5669c9f` 的[三项 CI](https://github.com/lich13/nexushub/actions/runs/37739015926) 全部通过，包含 Chromium/WebKit、后端完整门禁及 4 项新增 Tauri 状态保护测试。正式 App 仍为已发布的 1.2.9，不能把源码测试视为已修复实机。
